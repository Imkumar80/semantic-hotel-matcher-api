# Database Schema Architecture

The `semantic-entity-matcher` exports results to a SQLite database by default. Because entities differ radically in their fields, the database generation script uses the YAML configuration to build schemas dynamically.

## 1. Generic Table Structure

The core package builds two primary tables for any entity type.

### `canonical_entities`
Contains the deduplicated, finalized records representing a single real-world entity.

| Column | Type | Description |
| :--- | :--- | :--- |
| `id` | TEXT PRIMARY KEY | Unique UUID generated by the pipeline |
| `confidence` | REAL | The lowest internal edge weight in the resolved cluster |
| `source_a_ids` | TEXT | Comma-separated IDs from Supplier A |
| `source_b_ids` | TEXT | Comma-separated IDs from Supplier B |
| `[dynamic_fields...]` | VARIES | Dynamically generated columns mapped from CSVs (e.g., `name`, `price`) |

### `near_misses`
Tracks borderline candidate pairs that failed to meet the confidence threshold but may require human review.

| Column | Type | Description |
| :--- | :--- | :--- |
| `entity_id` | TEXT | FK to `canonical_entities.id` |
| `miss_id` | TEXT | The ID of the rejected candidate |
| `score` | REAL | The Splink prediction score for this pair |

---

## 2. Dynamic Schema Generation

The SQL schema is generated at runtime based on the `match_columns` definition in the YAML config.

**Example: Products Config**
```yaml
match_columns:
  product_name: { type: "text" }
  price: { type: "numeric" }
  category: { type: "text" }
```
**Translates to:**
```sql
CREATE TABLE canonical_entities (
    id TEXT PRIMARY KEY,
    confidence REAL,
    source_a_ids TEXT,
    source_b_ids TEXT,
    product_name TEXT,
    price REAL,
    category TEXT
);
```

---

## 3. Sub-Entity Tables (Example-Specific)

If a plugin implements the `SubEntityMatcher` interface (e.g., for Hotels), it is responsible for injecting its own schemas into the final database build process.

**Example: Hotel Rooms Plugin DB Injection**
```sql
CREATE TABLE sub_entities (
    sub_entity_id TEXT PRIMARY KEY,
    parent_entity_id TEXT, -- FK to canonical_entities.id
    name TEXT,
    capacity INTEGER,
    bed_type TEXT,
    source TEXT
);

CREATE TABLE sub_entity_matches (
    parent_a_id TEXT,
    parent_b_id TEXT,
    sub_entity_a_id TEXT,
    sub_entity_b_id TEXT,
    score REAL
);
```

### Hook Pattern
The `DatabaseBuilder` class provides an `execute_custom_sql()` method to allow plugins to seamlessly write their sub-entity data into the same SQLite file.
